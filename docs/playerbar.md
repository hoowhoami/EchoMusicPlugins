# 播放栏 API

`ctx.ui.playerbar.register()` 注册一个播放栏操作，宿主统一负责首页播放栏、歌词页底部控制栏、更多菜单、布局编辑、Tooltip、徽标显示和生命周期清理。插件无需自行挂载播放栏 DOM。

播放栏操作适合放置与当前播放、队列、音源、外部设备或轻量工具相关的入口。更完整的页面入口仍建议使用 `ctx.ui.sidebar.addItem()` 或 `ctx.ui.addPage()`。

## 注册操作

```ts
const dispose = ctx.ui.playerbar.register({
  id: 'open-panel',
  title: '插件面板',
  icon: 'tabler:music-cog',
  tooltip: '打开插件播放面板',
  defaultPlacement: 'more', // 'left' | 'center' | 'right' | 'more'
  trigger: 'click', // 'click' | 'hover'
  order: 100,
  badge: () => '3',
  badgeTitle: '待处理数量',
  badgeDefaultVisible: true,
  visible: () => true,
  disabled: () => false,
  onClick: async () => {
    // 打开插件页面、弹窗或执行播放相关操作。
  },
});

// 可主动注销；插件停用时宿主也会自动清理。
// dispose();
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 插件内稳定且唯一的操作 ID。不要因名称或版本变更而更换 ID，否则用户布局无法匹配。 |
| `title` | 是 | 更多菜单、编辑布局和无障碍名称。 |
| `icon` | 是 | Iconify 名称（如 `tabler:music-cog`）或图标数据对象，与侧边栏格式一致。 |
| `tooltip` | 否 | 默认为 `title`。播放栏按钮使用宿主 Tooltip；更多菜单日常模式已有文字，编辑模式使用标题提示。 |
| `defaultPlacement` | 否 | `'left'`、`'center'`、`'right'` 或 `'more'`，默认为 `'more'`。只决定初始位置，不能覆盖用户设置。 |
| `trigger` | 否 | `'click'` 或 `'hover'`，默认为 `'click'`。用于声明操作的交互语义，方便宿主和插件保持一致；普通命令用 `click`，需要悬停弹层体验的入口可用 `hover`。 |
| `order` | 否 | 默认 1000，数值越小越靠前；用户排序优先。同值以稳定操作标识确定顺序。 |
| `badge` | 否 | 字符串、数字、`null`，或同步函数。返回空值时不显示徽标；异常时隐藏徽标并上报插件错误。 |
| `badgeTitle` | 否 | 编辑布局中徽标复选框的提示名称，默认使用 `title`。 |
| `badgeDefaultVisible` | 否 | 徽标默认是否显示，默认 `true`。用户可在播放栏编辑布局中点击对应按钮后方的徽标复选框覆盖。 |
| `visible` | 否 | 布尔值或同步函数，默认 `true`。函数可读取 Vue 响应式状态；异常时隐藏。 |
| `disabled` | 否 | 布尔值或同步函数，默认 `false`。函数可读取 Vue 响应式状态；异常时禁用。 |
| `onClick` | 是 | `() => void \| Promise<void>`。异步执行期间禁用该操作，防止重复触发；异常交给插件运行时错误处理。 |

`visible`、`disabled` 和 `badge` 函数应无副作用。注册后更新响应式状态即可改变可见性、可用性或徽标内容；如果需更改标题、图标等描述，使用相同 ID 重新注册。

## 位置与用户管理

播放栏有四个可管理位置：

- `left`：歌曲信息下方的小按钮区。
- `center`：播放控制上方按钮区，适合与播放行为强相关的入口。
- `right`：播放栏右侧功能区。
- `more`：默认收纳到更多菜单。

播放栏“更多功能”弹出层分为两种状态：

- 日常模式只展示当前被收纳到更多菜单的可执行操作，用户点击即可执行。
- 编辑布局模式显示左下、中上、右侧、更多四区，用户可直接拖动按钮调整位置与顺序；支持徽标的按钮会在按钮后方显示“徽标”复选框，点击即可控制该按钮徽标是否显示。修改即时生效并自动保存，不需要额外确认。

空间不足时，宿主会把放不下的操作临时收入更多菜单。窗口恢复后自动回到保存的位置和顺序，保存的 `defaultPlacement` 与用户布局不会被临时溢出覆盖。

- 布局按插件 ID 与操作 ID 隔离。插件停用时移除入口，但保留用户偏好；重新启用或升级后恢复。
- `visible: false` 的操作在播放栏和更多菜单中均隐藏，但保留用户偏好。
- 恢复默认会清除播放栏的用户位置、排序和徽标显示偏好，重新采用每个操作的 `defaultPlacement`、`order` 和 `badgeDefaultVisible`。
- 宿主内置的播放、上一首、下一首、音质、音效、桌面歌词、播放队列等操作也参与同一套布局管理；插件操作会与内置操作混合排序。

## 生命周期

同一插件重复注册同一 ID 会替换旧操作；旧注册返回的注销函数不会删除新操作。已注销或已替换操作的旧回调无法再执行。插件停用、卸载时自动移除注册，正在执行的 Promise 不会被强制取消。

不要自行向播放栏插入 DOM 或监听播放栏内部结构。需要进入播放栏、歌词页底部控制栏或更多菜单时，使用 `ctx.ui.playerbar.register()`。
